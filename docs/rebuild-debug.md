# Пересобрать и перезапустить локальный Telegram

Из корня этого Windows checkout, в обычном cmd.exe или PowerShell:

```bat
.\rebuild-debug.cmd
```

Можно дважды щёлкнуть `rebuild-debug.cmd`. Открывать Native Tools Prompt
не требуется. Скрипт `Telegram/build/rebuild_debug.ps1` читает уже настроенный
`out/CMakeCache.txt` и использует CMake и Visual Studio именно этого build tree.
Требуется существующая нативная конфигурация Visual Studio x64 с MSVC 14.44;
первоначальная настройка описана в [local-windows-build.md](local-windows-build.md).
Для Linux/WSL и macOS этот скрипт не используется.

## Что происходит

1. Проверяются каталог исходников из cache, инструменты сборки и процессы.
   Блокировка `out/rebuild-debug.lock` не позволяет запустить два экземпляра
   этого скрипта одновременно. Не запускать параллельно ручную сборку того же `out`.
2. Инициализируется окружение `vcvars64.bat -vcvars_ver=14.44` из настроенной
   установки Visual Studio. Если окружение неисправно, клиент остаётся работать.
3. Если запущен именно `<checkout>\out\Debug\Telegram.exe` с аргументом
   `-workdir "<checkout>\out\local-profile"`, ему отправляется штатная команда
   `-quit` с тем же `-workdir`. Ожидается корректный выход клиента и команды
   завершения; по умолчанию до 30 секунд. Это работает и при сворачивании в трей.
4. Выполняется `cmake --build out --config Debug --target Telegram --parallel 6`.
   Вывод одновременно виден в консоли и записывается в `out/rebuild-debug.log`.
5. Только при коде сборки 0 запускается новый `out\Debug\Telegram.exe` с
   `-workdir "<checkout>\out\local-profile" -noupdate`. Проверяется, что процесс
   не завершился в первые три секунды. Это проверка старта, а не входа в аккаунт
   или работоспособности всех функций.

Если клиент до запуска скрипта не работал, после успешной сборки он всё равно
запустится. Профиль сохраняется: скрипт не удаляет `tdata`, папку профиля,
объекты сборки, EXE или PDB. Даже при ошибке сборки данные аккаунта остаются.
Неудачная сборка не приводит к запуску старого или недособранного EXE.

## Параметры

```bat
.\rebuild-debug.cmd -CheckOnly
.\rebuild-debug.cmd -Jobs 4
.\rebuild-debug.cmd -StopTimeoutSeconds 60
```

`-CheckOnly` проверяет конфигурацию, пути инструментов и подходящие процессы,
не закрывая клиент, не собирая и не запуская приложение. Реальную инициализацию
окружения компилятора и компиляцию проверяет обычный запуск.

При зависшем клиенте, остановке в отладчике, другом профиле этого EXE или
профиле, занятом другим EXE, скрипт завершается с ошибкой. Принудительного
завершения процессов нет. При блокировке EXE/PDB нужно закрыть именно локальный
клиент или его отладку и повторить команду. Установленный Telegram, другие
checkout и их профили не затрагиваются. Если процесс запускается из IDE без
явного абсолютного `-workdir`, закрыть его вручную перед запуском помощника.

## Разрешение для следующих сессий

Пользователь разрешил агентам самостоятельно использовать этот помощник,
когда работа над данным форком требует сборки и перезапуска. Повторное
подтверждение для штатного завершения указанного локального клиента не нужно.
Это разрешение записано в `AGENTS.md` в разделе `Build output locks`.
Оно не распространяется на принудительное завершение, другие Telegram,
отладчики, другие профили и удаление заблокированных файлов.

В последующих сессиях запускать команду из корня нужного checkout, дождаться
её окончания и проверить код завершения. Код 0 означает успешную сборку
и старт нового процесса. При ошибке читать `out/rebuild-debug.log`, если сборка
началась; ошибки предварительных проверок выводятся в консоль. Сообщать
конкретную причину, не обходить проверки заменой на `taskkill /IM Telegram.exe`.
