# Пересобрать и перезапустить локальный Telegram

Из корня этого Windows checkout, в обычном cmd.exe или PowerShell:

```bat
.\rebuild-debug.cmd
```

Можно дважды щёлкнуть `rebuild-debug.cmd`. Открывать Native Tools Prompt
не требуется. Скрипт `Telegram/build/rebuild_debug.ps1` читает уже настроенный
`out/CMakeCache.txt` и использует CMake и Visual Studio именно этого build tree.
Требуется существующая нативная конфигурация Visual Studio x64 с MSVC 14.44;
первоначальная настройка описана в [local-windows-build.md](local-windows-build.md).
Для Linux/WSL и macOS этот скрипт не используется.

## Что происходит

1. Проверяются каталог исходников из cache, инструменты сборки и процессы.
   Блокировка `out/rebuild-debug.lock` не позволяет запустить два экземпляра
   этого скрипта одновременно. Не запускать параллельно ручную сборку того же `out`.
2. Инициализируется окружение `vcvars64.bat -vcvars_ver=14.44` из настроенной
   установки Visual Studio. Если окружение неисправно, клиент остаётся работать.
3. Выполняется `cmake --build out --config Debug --target Telegram --parallel 6`.
   Во время компиляции клиент продолжает работать. Вывод виден в консоли
   и записывается в `out/rebuild-debug.log`.
4. Непосредственно перед линковкой CMake вызывает `PRE_LINK` из
   `Telegram/cmake/fork_options.cmake`. Скрипт `rebuild_debug_pre_link.ps1`
   проверяет запрос текущего запуска помощника и заново проверяет процессы.
   Если запущен именно `<checkout>\out\Debug\Telegram.exe` с аргументом
   `-workdir "<checkout>\out\local-profile"`, ему отправляется штатная команда
   `-quit` с тем же `-workdir`. Ожидается корректный выход клиента и команды
   завершения; по умолчанию до 30 секунд. Это работает и при сворачивании в трей.
   При неудачном завершении линковка не начинается.
5. Только после кода 0 всей сборки, включая действия после линковки, запускается
   новый `out\Debug\Telegram.exe` с
   `-workdir "<checkout>\out\local-profile" -noupdate`. Проверяется, что процесс
   не завершился в первые три секунды. Это проверка старта, а не входа в аккаунт
   или работоспособности всех функций.

При ошибке компиляции `PRE_LINK` не выполняется: работающий клиент остаётся
открытым. MSBuild может вызывать `PRE_LINK` даже при неизменившихся исходниках:
в этом случае клиент тоже перезапускается. Если хук вообще не выполнялся,
существующий процесс остаётся работать. Если клиент не работал, после успешной
сборки он запускается,
даже когда сборка не потребовала линковки. При ошибке линковки или последующих
шагов помощник не запускает старый или недособранный EXE.

Профиль сохраняется: скрипт не удаляет `tdata`, папку профиля, объекты сборки,
EXE или PDB. Даже при ошибке сборки данные аккаунта остаются.

Хук включается только на время команды помощника через переменную окружения
`TDESKTOP_REBUILD_DEBUG_RUN` и файл `out/rebuild-debug-session.json` с уникальным
идентификатором запуска и PID владельца. После команды контекст удаляется,
прежнее значение переменной восстанавливается. Сам по себе хук в обычной ручной
сборке никого не закрывает; вручную выставлять эту переменную не нужно.
Общая проверка процессов и штатное завершение находятся в `debug_client.ps1`.

## Release

```bat
.\rebuild-release.cmd
```

Запускает тот же скрипт с `-Configuration Release`: собирается и перезапускается
`out\Release\Telegram.exe` с тем же профилем `out\local-profile`, журнал —
`out/rebuild-release.log`. Требуется, чтобы `out` был настроен с Release
в `CMAKE_CONFIGURATION_TYPES` и подготовленными Release-зависимостями
(см. [local-client-launch.md](local-client-launch.md)). Хук `PRE_LINK`
закрывает только клиент той конфигурации, которая сейчас собирается.
Если профиль занят клиентом другой конфигурации, скрипт завершается
с ошибкой до сборки.

Release — ежедневный клиент. Debug нужен для отладки: в нём работают
пошаговая отладка, проверка итераторов, отладочная куча и проверки Qt.

## Параметры

```bat
.\rebuild-debug.cmd -CheckOnly
.\rebuild-debug.cmd -Jobs 4
.\rebuild-debug.cmd -StopTimeoutSeconds 60
.\rebuild-release.cmd -CheckOnly
```

`-CheckOnly` проверяет конфигурацию, пути инструментов и подходящие процессы,
не закрывая клиент, не собирая и не запуская приложение. Реальную инициализацию
окружения компилятора и компиляцию проверяет обычный запуск.

При зависшем клиенте, остановке в отладчике, другом профиле этого EXE или
профиле, занятом другим EXE, скрипт завершается с ошибкой. Принудительного
завершения процессов нет. При блокировке EXE/PDB нужно закрыть именно локальный
клиент или его отладку и повторить команду. Установленный Telegram, другие
checkout и их профили не затрагиваются. Если процесс запускается из IDE без
явного абсолютного `-workdir`, закрыть его вручную перед запуском помощника.

## Разрешение для следующих сессий

Пользователь разрешил агентам самостоятельно использовать `rebuild-release.cmd`,
когда работа над данным форком требует сборки и перезапуска. `rebuild-debug.cmd`
агенты запускают только по просьбе пользователя, например для отладки падения.
Повторное подтверждение для штатного завершения указанного локального клиента
не нужно. Закрытие должно происходить только перед линковкой, а не перед
компиляцией. Это разрешение записано в `AGENTS.md` в разделе `Build output locks`.
Оно не распространяется на принудительное завершение, другие Telegram,
отладчики, другие профили и удаление заблокированных файлов. Если профиль занят
клиентом другой конфигурации, агент не закрывает его, а просит пользователя.

В последующих сессиях запускать команду из корня нужного checkout, дождаться
её окончания и проверить код завершения. Код 0 означает успешную сборку
и работающий клиент: новый процесс после срабатывания хука либо прежний,
если хук не выполнялся. При ошибке читать `out/rebuild-release.log`
или `out/rebuild-debug.log`, если сборка началась; ошибки предварительных
проверок выводятся в консоль. Сообщать конкретную причину, не обходить
проверки заменой на `taskkill /IM Telegram.exe`.
